Deepavali petal texture prototype

Open Assets/Scenes/Deepavali_TexturedPetalTest.unity. Earlier plain test scenes
are preserved. The reusable prefab is Deepavali Textured Inner Layer.prefab in
Assets/HK_Signature/Deepavali/PetalPrototype/Prefabs/.

No remeshing or new UV unwrap was required. The existing ArtworkUV channel maps
the planar petal across U (width) and V (root=0, tip=1). The FBX, 191 petal
vertices, 324 triangles, three bones, skin weights and picking are unchanged.

Two visual regions, one URP/Lit material:
- Textures/Petal_Deepavali_BaseColor.png: burgundy surface with a gold/saffron
  lotus-flame and curling Deepavali ornament. sRGB base color, responds to lights.
- Textures/Petal_EdgeEmission.png: grayscale emission mask, imported as linear
  data. White is the edge light; black leaves the center non-emissive. Generated
  from the actual UV mesh boundary, not an approximate painted outline. Nominal
  2 mm ribbon sits 3 mm inside the 0.182 m x 0.263 m planar petal silhouette.
- Materials/Petal Deepavali Lit.mat combines the two. No extra material slots,
  submeshes, geometry, transparency layers or per-petal material instances.

Both runtime maps are 512 x 1024, mipmapped, clamped, CPU readback disabled.
Android override: ETC2_RGB4. Two maps plus mipmaps use approximately 0.67 MiB
of compressed texel storage, shared by all eight petals; driver/engine overhead
is additional. Device performance and an Android build have not been measured.

Uniform edge color
FlowerEmissionController on the flower root owns one shared runtime material
for all eight petals and restores the asset materials when disabled. In Play
Mode, change Edge Color / Edge Intensity in its Inspector, or call:
    controller.SetEdgeColor(new Color(0.15f, 0.65f, 1f)); // sRGB input
    controller.SetEdgeIntensity(3f);
Intensity 0 switches the lights off. Color changes do not affect the center
artwork or its lighting. Successful petal picks now call TriggerFlash(): a short
rose-pink flash across all petal edges, followed by a return to the current base
color. Other stimulus handlers can call that method or the setters above.

Emission produces a bright visible surface. It does not itself create dynamic
light on the ground/other petals. The test now includes subtle screen-space
bloom at quarter resolution, limited to three levels with bilinear filtering.
HDR and post-processing are enabled on the test camera. Separate real lights
would be needed for dynamic light spill. See output/flower-petal-feedback/README.txt
for settings and validation of the tap feedback and bloom.

URP's material validator requires an emissive GI flag to retain the _EMISSION
keyword. The asset uses BakedEmissive, but these moving petals are non-static;
this setup does not bake or update GI from their runtime color changes.

Validation
emission-validation.json: uniform color across one shared runtime material,
zero intensity, unchanged artwork, disable/reenable and asset restoration.
motion-validation.json: eight independent clicks, two simultaneous touches,
ignored disc/gap/background positions, fixed roots and culling bounds; passed
with the mobile pipeline in the desktop Editor. No runtime errors.

Artwork produced with the built-in image_gen tool. The full prompt and reference
roles are saved in artwork-prompt.txt. The mask/guide are technical UV data
generated by build_uv_masks.py. The image generator did not produce the mask.
